# PZ 存档备份工具 (PZ Save Backup)

[English](README.md) | 中文

僵尸毁灭工程（Project Zomboid）存档定时自动备份小工具。纯 Python + tkinter，零第三方运行依赖。
**界面支持中英双语**（右上角切换，选择会记住）。

**备份方式**：把存档文件夹原样复制一份，**就放在存档目录里、与原存档并排**，
文件夹名是 `<存档名>_YYYYMMDD_HHMMSS`。

```
%USERPROFILE%\Zomboid\Saves\Sandbox\
├─ 快乐僵毁\                              ← 原存档
├─ 快乐僵毁_20261015_140620\              ← 它的备份（备份 1）
├─ 快乐僵毁_20261015_161205\              ← 它的备份（备份 2）
└─ 大雾天气艰难求生1 - 副本\
```

恢复时把备份文件夹拷回存档目录、改名去掉 `_时间戳` 即可；或者直接把备份里的内容覆盖回原存档文件夹。

## 怎么认出来哪些是备份

靠文件名：

* `<存档名>_YYYYMMDD_HHMMSS` → 备份
* 同名的第 2、3 份会带序号：`<存档名>_YYYYMMDD_HHMMSS_2`
* 别的名字 → 原存档（PZ 自带的默认存档名 `2026-10-15_12-46-42` 用的是横杠，不会被误判）

**例外（重要）**：备份如果被拿去继续玩，它就变回"存档"——会出现在存档列表里（橙色标注"在玩的备份"）、
自动勾选、并且可以被继续备份（生成的备份名是 `<原名>_<旧时间戳>_<新时间戳>`，层层往下都能玩能备份）。

判定用两个信号，命中任一即可：

| 信号 | 说明 |
| --- | --- |
| ① 游戏自己记的 | `Zomboid\latestSave.ini` 第一行写的就是**最近加载过的存档名**。你加载了哪个备份玩，它就写哪个——最权威，刚做的备份立刻开玩也能认出来 |
| ② 文件被写过 | 备份里有文件的时间晚于它自己名字里的时间戳（+60 秒容差），且在"现在"之前。玩过之后游戏写档，mtime 就跳上去了 |

反过来，**静止的备份两条都不满足**，所以不会被当成存档、不会被重复备份；
时间戳落在"未来"的文件（时钟回拨、从别处拷进来的）也不算证据，避免误判。

**改名时备份会跟着走**：把 `快乐僵毁` 改名成 `快乐僵毁2`，它的备份 `快乐僵毁_20261015_140620`
会一起改成 `快乐僵毁2_20261015_140620`（时间戳和 `_2` 序号都保留），所以备份永远认得到自己的存档。

## 自动备份怎么跑

开启后每 N 分钟（可配置，1 ~ 1440）**到点**，然后：

1. **先等时机**——检查所有监控中的存档有没有在被写（文件最新修改时间距现在 ≥「静止秒数」，默认 5 秒）。
   还在写就每 2 秒重查一次，最多等 180 秒；等不到就放弃本轮（下轮再试），**绝不在写档中途动手**。
2. **比指纹**——和这份存档最近一次备份比（文件数 / 总字节 / 最新修改时间），没变化就跳过。
3. **全量复制**——一个文件不落地复制；任何一个文件读不了，整次失败（**不留缺文件的残缺备份**）。
4. **复制期间源被写过就作废**——复制完成后再比一次源指纹，变了就把刚做好的备份删掉并提示，
   因为半新半旧的备份拿去恢复会**把存档弄坏**。
5. **重新计时**——备份结束后定时器才重新开始计时（不是按固定节拍硬撞）。

这就是为什么**游戏里玩着的时候备份是安全的**：写档时工具根本不动手，等它安静下来才复制。

所以**不需要手动选存档**：所有存档都自动盯着，新出现的存档（包括你拿旧备份继续玩的那种）也会自动加入监控。
真想让某个存档不参与，在列表里点它一下取消勾选（☐）即可；一个都不勾时会自动恢复成全监控。

主界面右栏会实时显示现在能不能备份：绿色「存档已静止 X 秒，可以安全备份」/ 橙色「⚠ 正在写入…暂不备份」。

## 功能

| 功能 | 说明 |
| --- | --- |
| 定时自动备份 | 间隔可配置（1 ~ 1440 分钟）；到点先等存档静止，备份完成后再重新计时 |
| 写入保护 | 写档中绝不备份（静止需 ≥5 秒，可调）；备份途中源被写过，这次备份直接作废删除 |
| 只备份有变化的 | 拿存档和它最近一份备份比指纹（文件数 / 总字节 / 最新修改时间），没变化就跳过，不重复复制 |
| 全量备份 | 一个文件不落；某个文件读不了就整次失败，**绝不产出缺文件的残缺备份** |
| 选择存档 | 默认监控全部，不用挑；点一下取消勾选（☐）可以排除某个存档；新出现的存档自动加入监控 |
| 重命名存档 | 双击、右键菜单或右侧「重命名」按钮，直接改存档文件夹名；**它名下的备份会一起改名**，不会变成认不到主人的孤儿 |
| 删除存档 | 右键菜单、右侧「删除」按钮或高级页按钮，移入回收站（可还原），带二次确认 |
| 分类归纳 | 每个存档在列表里显示备份份数；下方备份区用下拉框选存档，列出它全部的备份（双击打开、右键改名/删除） |
| 自动探测存档目录 | 读 `latestSave.ini` 与 `Saves` 目录，可随时手动更改，配置存在 `config.json` |
| 保留份数 | 每个存档只保留最近 N 份，超出的自动移入回收站（0 = 不清理）；**正在被当成存档玩的那种备份永不清理** |
| 完整性校验 | 复制完成核对该有的文件一个不少；单个文件被占用会重试 4 次，仍失败则**整次失败并清掉半成品**，不留残缺备份 |
| 兼容旧备份 | 早先用过的 `.zip` 备份也会显示在列表里（标注「旧版 zip」），可以一起改名/删除 |

## 界面

窗口默认 620×420，可拉伸。页签按钮就在标题「PZ 存档备份」右边。

**备份**（主界面）
* 左上是**存档列表**：默认全部监控（`☑`），点一下切换成排除（`☐`）；「备份」列显示每个存档有几份备份；橙色行 = 从备份继续玩的存档
* 左下是**备份区**：下拉框选择要看哪个存档的备份，下面是它全部的备份（双击在资源管理器打开，右键可改名/删除）
* 右侧：备份间隔、`▶ 开始自动备份` / `⏱ 立即备份`、存档「重命名 / 删除」、下次备份倒计时与进度

**高级**
* 备份位置（默认"同目录"，也可以改成别处 / 切回同目录）
* 每个存档保留份数、开启即备份一次、存档没变就跳过
* 批量操作：全选 / 全不选 / 重命名存档 / 删除存档 / 打开存档目录 / 刷新
* 左：备份记录总览　右：日志

## 快速开始

```bat
python pz_save_backup_gui.py     :: 直接运行
run_gui.bat                       :: 或双击
```

自检（临时目录跑一遍复制/识别/指纹/定时器逻辑，不动真实存档）：

```bat
python pz_save_backup_gui.py --selftest
python tests\gui_smoke_test.py      :: 界面链路（分类、变化检测、玩过的备份、静止保护、途中被写）
python tests\schedule_test.py       :: 定时机制（到点→等时机→备份→重新计时）
python tests\locked_file_test.py    :: 文件被占用 / 边写边备份
python tests\config_test.py         :: 配置文件位置、迁移、写失败上报
python tests\i18n_test.py           :: 中英双语、运行时切换、选择持久化
```

## 编译成 exe（Nuitka）

```bat
pip install nuitka Pillow
python create_icon.py             :: 可选：生成 app_icon.ico
python build_nuitka.py            :: 默认编译成单文件 exe
python build_nuitka.py --onedir   :: 编译成文件夹（启动更快）
python build_nuitka.py --no-test  :: 编译完不自动试运行
```

产物：`dist_nuitka\PZ存档备份工具.exe`

## 目录说明

```
pz_save_backup_gui.py   主程序（GUI + 备份引擎 + 定时器 + 自检）
build_nuitka.py         Nuitka 编译脚本
create_icon.py          纯代码生成图标 app_icon.ico
run_gui.bat             一键启动
tests/                  自检与冒烟测试
```

**配置文件位置**（不再放在程序/exe 旁边，避免 exe 放在只读目录时写不进去）：

```
<你的文档>\PZSaveBackup\config.json
例如 C:\Users\你\Documents\PZSaveBackup\config.json
```

* 文档目录走的是 Windows 系统 API，OneDrive 重定向过的机器也能找到正确位置
* 第一次运行新版时，如果程序/exe 旁边还留着老 `config.json`，会自动搬过去，设置不会丢
* 万一文档目录也写不进去，会自动退回程序目录，并在日志里把错误**明确报出来**（不再静默失败）
* 日志第一行会写清楚这次用的是哪个配置文件

`config.json` 字段：

```json
{
  "saves_root": "C:\\Users\\<你>\\Zomboid\\Saves\\Sandbox",
  "backup_root": "",
  "backup_mode": "same_as_saves",
  "interval_minutes": 30,
  "keep_count": 10,
  "backup_on_start": true,
  "skip_unchanged": true,
  "only_when_idle": true,
  "idle_seconds": 5,
  "language": "zh",
  "selected_saves": null,
  "window_geometry": "620x420+450+206"
}
```

* `backup_mode`：`same_as_saves` = 备份放在存档目录里（默认）；`custom` = 用 `backup_root` 指定的目录
* `only_when_idle` / `idle_seconds`：只在存档静止（默认 5 秒没被写）时备份——**强烈建议保持开启**
* `selected_saves`：`null` = 还没设置过（默认全部勾选）；`[]` = 一个都不勾选

## 恢复存档

1. 关掉游戏。
2. 在存档目录里找到要恢复的备份文件夹，例如 `快乐僵毁_20261015_140620`。
3. 用法一：把它复制一份、改名去掉 `_20261015_140620`（得到 `快乐僵毁`），原来的存档先改名留底。
   用法二：直接把备份文件夹里的内容覆盖回原存档文件夹。
4. 启动游戏，存档列表里就能看到它了。

## 游戏运行时备份，会被文件占用挡住吗？

不会中断，也不会静默出坏备份：

* 单个文件复制失败会重试 4 次（等 0.2s / 0.4s / 0.8s），游戏写档的毫秒级占用基本能救回来。
* 重试仍失败的文件会被跳过，备份照常完成，但会明确告诉你：日志标红 `⚠ xxx 不完整：players.db 没复制进去`，并弹窗警告「有备份不完整」。
* 能读到但游戏正在写入的文件，复制到的是**那一瞬间**的内容，不保证是前后一致的整体快照；要求高就退出游戏再备份。

## 注意

* **备份和存档在同一个文件夹里，所以游戏也会把这些备份列进存档列表**（后备箱里多了一堆名字带时间戳的存档）。这是"同目录"方案的必然结果，别手滑点进去玩；真误进了，退出别存档就行。
* 备份是完整复制，占用空间和原存档一样大（不会像 zip 那样压缩）；配合「保留份数」自动清理。
* 删除存档、删除备份都是移入回收站，误删可从回收站还原。
* 备份文件夹名请别手动改成别的格式，否则工具会认不出它是备份（会当成原存档）。
